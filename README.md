# Claude Code 繁體中文回話風格（Output Style）

用 Claude Code 的 output style 功能，把「AI 助理該怎麼跟你說話」寫成一個檔案。這個 repo 是我們實際在用的版本，含完整的痛點、設計想法與安裝步驟。

檔案只有一個：[`output-styles/zhtw-style.md`](output-styles/zhtw-style.md)。

## 痛點：為什麼要管 AI 的說話方式

這些都是長期使用累積出來的真實痛點，不是想像出來的：

1. **簡體字混入**。你用繁體問，它用繁體答——直到它查了一篇簡體資料，接下來整段回答就跟著變簡體。對只讀繁體的使用者，這等於看不懂。
2. **中英夾雜**。「這個 approach 的 tradeoff 是……」讀起來很累。術語可以留英文，敘述不行。
3. **簡單問題長篇大論**。問一句「這是什麼」，回來一張 18 列的比較表加五個小節。
4. **術語轟炸**。丟出 α、t 值、σ 卻不翻譯成白話，也不套回你自己的數字。
5. **報喜不報憂**。說「做完了」但沒證據；查詢逾時被寫成「查無資料」；跳過的步驟不講。
6. **規則寫了不執行**。以上每一條都寫過規則，但規則放在筆記裡，模型想不起來就等於不存在。

## 原因：這些毛病從哪來

- **訓練資料分布**：中文語料以簡體為大宗，模型的中文「預設腔」偏簡體與大陸用語。
- **語言漂移的入口在讀取，不在輸出**：模型傾向跟隨 context 裡最近出現的語言。讀了簡體資料，輸出就被帶走。所以只叮嚀「輸出前自查」治標，要從入口鎖定。
- **有用性偏好**：模型被訓練成「多給一點比較保險」，於是簡單問題也給出完整報告。
- **規則的送達方式**：放在記憶或筆記裡的規則是「機率性存在」——被檢索到才有效。output style 每個 session 保證注入，這是它跟筆記最大的差別。

## 想法：設計上的幾個決定

**風格層與業務規則分層。** output style 只管「怎麼說話」，專案的業務規則（該做什麼、怎麼派工）留在 CLAUDE.md。兩層各自演化，互不重複。

**語言鎖定管入口。** 規則寫成「回覆語言只由使用者當次訊息決定，整輪不變；禁止從讀進來的資料推斷語言」。這是治根因的那一條——簡體混入幾乎都來自「查了簡體材料就跟著用」。

**借 STE100 的原則層。** ASD-STE100 是航太業的受控語言規範（Simplified Technical English），核心是一詞一義、一句一事、句短、主動語態。原版管的是英文詞彙表與文法，詞彙表搬不動，但原則可以在地化成中文寫作規則。技術溝通的可讀性問題，航太業五十年前就解過一輪。

**收據文化：用輸出格式逼出執行。** 「要誠實」這種原則性規則會被靜默跳過，因為沒有任何東西檢查輸出裡有沒有它。改成硬性格式——派過工就必須附一行 `[派工收據]`，查過資料庫就必須附進度表——沒附就等於沒做完。規則要進輸出格式，否則是裝飾。

**留一個違規訊號。** 使用者說「我看不懂」「太多術語」，定義為當場違規，立刻重講白話版。這給了風格一個可執行的回饋迴圈，而不是抽象的期許。

## 實際操作：安裝三步

1. 建目錄（已存在就跳過）：

   ```bash
   mkdir -p ~/.claude/output-styles
   ```

2. 把 [`output-styles/zhtw-style.md`](output-styles/zhtw-style.md) 複製進去：

   ```bash
   cp output-styles/zhtw-style.md ~/.claude/output-styles/
   ```

3. 在 Claude Code 裡執行 `/config`，找到「輸出風格（Output style）」，選「繁中簡明風格」。

改了檔案內容之後，重選一次風格或開新 session 才會生效。

## 檔案格式說明

output style 是一個帶 YAML frontmatter 的 markdown 檔：

```markdown
---
name: 顯示在選單上的名稱
description: 一句話說明
---

（以下整段會注入 system prompt，取代預設的回話風格指示）
```

`name` 是 `/config` 選單上看到的名稱。內文就是給模型的指示，寫法沒有限制——我們的經驗是：規則要可檢查（「句短」附上字數目標）、例外要明列（哪些東西保持原文）、違規要有訊號（什麼話等於踩線）。

## 改成你自己的版本

`zhtw-style.md` 裡有幾條是我們的環境特化，改掉就能通用：

- 「金額單位一律億美元」——投資研究場景的慣例，不需要就刪。
- 收據文化那節引用了我們的派工詞彙（lane、機械／判斷），可以整節刪掉，或換成你自己的檢查格式。
- 風格名稱由 frontmatter 的 `name` 欄位決定，隨你改。
